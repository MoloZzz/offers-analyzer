# Domain glossary (ubiquitous language)

> The shared vocabulary of the offers domain. Use these exact terms in code, specs, and conversation. Add a term the first time it appears.

| Term | Definition | Notes / synonyms to avoid |
|------|------------|---------------------------|
| **Listing** | A single car advertisement on a source (auto.ria `auto_id` + details). | Prefer over "offer" for a raw ad. |
| **Cohort** | The set of comparable cars used to value a listing. Definitions include mileage-banded, year±1 nationwide, and make+model; the live ingestion path currently begins with reusable year±1, then make+model, while retaining analytical mileage adjustment ([[0013-budget-stabilization-before-lifecycle-rechecks|ADR-0013]]). City is never used (starves the sample). | — |
| **Newest by market** | An ingestion mode: a search profile with **empty make/model** + region + price cap that pulls the freshest listings market-wide, using AUTO.RIA's `top` **submission-period** filter (1=last hour, 2=today, 8=last 3h…). Each is still valued against its own cohort. | Not an `order_by` sort — RIA has no "newest" sort. |
| **Fair value (FV)** | Estimated market price for a listing's cohort; v1 uses AUTO.RIA percentile-50 (median), with interquartile/arithmetic fallbacks. Claimed low mileage raises it only with VIN evidence and is capped at 5% after 15 years ([[0014-conservative-benchmark-and-mileage-guard|ADR-0014]]). | See [[profitability-definition]]. |
| **Active-market asking-price estimate** | A timestamped provider estimate of what comparable listings are actively advertised for. SPEC-015 uses it only as shadow evidence; it is not a confirmed sale, likely transaction price, quick-exit price, or buy ceiling. | Do not call it “real market price” or reuse the legacy `fairValue` name. |
| **Valuation evidence** | An immutable, redacted record of one provider valuation attempt: target, input facts/provenance, query mode, policy/adapter version, response summary, comparability decision, and terminal reason. Its timestamp is provider as-of time only when supplied; otherwise it is explicitly a local response-capture time. | Stored so `/why` can explain history without a source re-fetch. |
| **Valuation policy version** | An immutable rule set for a provider evidence target: required facts, allowable relaxations, freshness, sampling, and quality decisions. | Separate from a scoring `ParameterSet`; SPEC-015 starts with shadow-only `ai-shadow-v1`. |
| **Valuation AI allocation** | The configured per-month request allowance for the `valuation_ai` operation inside the shared AUTO.RIA budget. It is checked atomically before every provider attempt and defaults to zero. | A zero allocation blocks all paid provider requests; it is distinct from the automatic sampling rate. |
| **Discount** | `(FV − asking) / FV` — how far below market a listing is priced. | — |
| **Opportunity** | A listing flagged as having a **high probability of operator profit on resale** ([[0006-operator-profit-vision|ADR-0006]]): strong price core (discount + confidence + red-flags) shaped by the factor modifiers below. | Not a guarantee of profit. |
| **Total Deal Score** | The composite ranking signal: price core (`raw × confidence × penalty`, where `confidence` is the **cohort sample-size** term — not **Assessment confidence** below; dominant) × bounded factor modifiers (liquidity, repair-risk, negotiation, seller, positives). Shown to the operator as 0–100 + per-factor reasons. Spec `003-composite-deal-score`; liquidity + repair-risk are implemented but **intentionally inactive until the survivorship correction `k` lands** ([[0010-defer-factor-activation-until-k|ADR-0010]]). Activation needs the evidence gates in [[0011-evidence-gated-scoring-rollout|ADR-0011]]. | Supersedes "Opportunity score = discount × confidence". |
| **Liquidity score** | How easily a model resells (heuristic tiers by make/model/segment: Camry/Octavia high; XF/C6 low). Bounded modifier + reasons. | ≠ market demand (segment turnover speed — later). |
| **Repair-risk score** | Model-level expected-repair-cost heuristic (DSG/CVT/air suspension/aged premium diesels → HIGH; Corolla/Camry → LOW). Distinct from listing-level red-flags. | Bounded dampening, never a hard disqualifier by itself. |
| **Negotiation signal** | Seller-motivation cue parsed from the description («торг», «терміново», «переїзд»…), negation-aware. Bounded uplift. | — |
| **Positive signal** | Concrete quality evidence in the description (1 owner, service book, 2 keys, garage kept, factory LPG…). Bounded uplift + reduces `unverified_bargain` dampening (ADR-0006 §4 — supersedes "positives never inflate"). | Promotional fluff never fires (anti-gaming). |
| **Red-flag** | A risk condition that disqualifies/penalizes a cheap listing (write-off, unclear customs, scam-cheap, etc.). Sources: AUTO.RIA `autoInfoBar` flags **and** condition signals parsed from the seller description (non-runner, needs-repair — negation-aware). | Accident presence is **still** disqualifying in production; graded severity replaces it only at the spec-018 phase-3 flip — see **Accident severity** below ([[0020-graded-accident-risk|ADR-0020]]). |
| **Accident severity** | A graded verdict — `cosmetic` / `moderate` / `severe` / `unknown` — derived from the AUTO.RIA damage bar plus a versioned uk+ru lexicon (spec `018-graded-accident-risk`). Once flipped, `severe` and salvage stay hard disqualifiers and the rest become bounded penalties. | **Recorded in shadow since 2026-08-03; not yet acting.** Seller text may **raise** severity freely but may **lower** it below `unknown` only with VIN corroboration — the same asymmetry [[0014-conservative-benchmark-and-mileage-guard|ADR-0014]] applies to claimed mileage. |
| **`unknown` severity** | `damaged = true` with no lexical evidence — the expected modal case. After the flip it carries a bounded penalty **and** a verify-before-travelling marker. | Means "we do not know how bad", never "it was minor". Wording that implies minor damage is a defect. |
| **Shadow verdict** | A classifier output computed and persisted on every evaluation while the behaviour it would change stays untouched — the accident severity is the first one. Its purpose is to make a scoring change *measurable before it is made* ([[0011-evidence-gated-scoring-rollout|ADR-0011]]). | A shadow verdict that any scoring path reads is no longer a shadow verdict. |
| **Suppressed listing** | A listing the live accident clamp disqualified where graded severity would not have — i.e. every disqualifier that fired was an accident one and the verdict was not `severe`. The unit the `/accident_shadow` rollout report counts. | A listing also killed by `suspicious_discount`, `salvage`, `confiscated`, `under_credit` or `desc_not_running` is **not** suppressed by the accident clamp; counting it would overstate the case for flipping. |
| **Search profile** | A configured niche to monitor within the API budget. | — |
| **Source adapter** | Implementation of the `ListingSource` port for one site (auto.ria = first). | — |
| **Outcome** | The realized result of a flagged listing — `manual` (operator 👍/👎, bought/skipped/resold) or `passive` (price_dropped, disappeared). The ground truth for spec-002 precision + learning. Manual is idempotent per opportunity; passive is deduped per (listing, label). | Weak passive signals ≠ confirmed profit. |
| **Deal outcome** | The operator's *real economics* after an alert, held in a separate stateful `deal_outcomes` record (one row per listing, upserted `declined → bought → sold`): `stage`, `declineReason`, buy/costs/sell USD, realized DOM. Distinct from **Outcome** — that is a 👍/👎 *label* stream; this is money, so it can (US7.3) replace 👍-precision as the auto-tuning target. Spec `007-deal-outcomes` (US7.1–7.2 implemented 2026-07-23). | Not consumed by spec-002 tuning yet — kept separate until CHANGE-002.1. |
| **Realized margin** | Money actually made on a closed deal: `sell_price − buy_price − actual_costs` (costs default 0; null unless both prices present). Aggregated as median margin + share of loss-making deals + median realized DOM over **closed deals** (sold with both prices), shown in `/report` and `/deals`. Spec 007 US7.2. | Computed, never stored. A **closed deal** = `stage='sold'` with buy+sell both present. |
| **Decline reason** | Why the operator walked away from an alerted car — `condition` / `documents` / `seller` / `price` / `other`, captured in two taps (❌ Відмова → reason). Surfaces the flags a physical inspection catches but scoring misses. Spec 007 US7.1. | Enum, one-tap; not free text. |
| **CalibrationRun** | A recorded threshold-calibration pass — inputs (per-profile scores, precision), the bounded proposal, whether it was applied, and why. Propose-only in v1. See spec 002. | Audit + revert trail. |
| **Calibration readiness gate** | The evidence report required before a candidate `ParameterSet` can affect live scoring: eligible disappearance count by cohort/fallback tier, void/relist rates, bootstrap interval and cohort stability for `k`, persisted evaluation explanations, and operator approval. | `≥15` closed deals authorizes a review, not auto-apply. See [[0011-evidence-gated-scoring-rollout|ADR-0011]]. |
| **ParameterSet** | A versioned, active bundle of scoring tunables (`scale`, soft-flag penalty, mileage factors) that live scoring reads at runtime — replaces hard-coded constants; enables tuning + rollback. One active version at a time. See [[0005-versioned-parameter-sets|ADR-0005]]. | Not the per-profile `minDealScore` (that's profile config). |
| **Evaluation explanation** | A persisted scoring-time snapshot stored on every evaluated `Listing.lastExplanation` and copied to `Opportunity.explanation`: cohort key/tier/sample, fair-value base/adjusted values, mileage adjustment, score breakdown, fired flags, `ParameterSet` version, threshold, and timestamp. `/why` prefers this snapshot before any live source call. | B23 closes reproducible historical explanations; matched phrases/richer localization remain polish. |
| **Evaluation breakdown** | The ordered, labelled projection of an **Evaluation explanation** that every operator-facing surface renders: sections in decision order (identity, price, cohort, mileage, provider evidence, score, factors, flags, confidence, monetary, verdict), each line carrying `label`, `value`, and an explicit `availability`. Built by one pure builder (`format/breakdown.ts`, spec 016); reached from an alert by the 📋 **Деталі** button, from `/why` in flat form, and from `/check`. | It **computes nothing** — a value not present in the record is a stated gap, never a recomputation. Adding a parameter is one edit, in the builder. |
| **Availability (breakdown line)** | Per-parameter state in an **Evaluation breakdown**: `available`, or `unavailable` with a machine-readable reason (`schema`, `unmeasured`, `inactive`, `live`, `suppressed`, `not-collected`). A V1/V2 snapshot reports a spec-006 field as *"the measure did not exist yet"*; a V3 carrying `null` reports *"it was not measured"*. | Never `0`, never a bare dash, never an invented value (spec 016 FR-004). Same discipline as the SPEC-015 `ValuationFact` shape. |
| **Survivorship correction (`k`)** | Candidate coefficient correcting `fair_value` for length-biased sampling: RIA's `average_price` is measured over *active* (unsold) listings, so overpriced cars — which sit far longer — are over-represented and inflate the average. `k = median(last-known asking price of filtered disappearances) / median(cohort average on disappearance date)`; computed per cohort with fallback make+model → make → global. | A disappearance and last asking price are only proxies for a sale and its realized price. Apply only after the calibration readiness gate; `k ≥ 0.97` falsifies the hypothesis. |
| **Disappearance** | A listing that stopped appearing in *detection-eligible* searches (no `submittedWithin` window, untruncated result, profile still covers it) for > 24h grace — recorded once per listing as a `ListingDisappearance` event (cohort key, last known USD price, DOM, price-cut stats) and treated as a *candidate* sale for `k`. Reappearance resurrects the listing and voids the event. Spec 004. | Disappearance ≠ sale — could be delisted/expired/banned; the `dom_days < 60` + relist filters select plausible sales. |
| **Sweep profile** | A search profile (`filters.sweep: true`) whose market-wide niche exceeds one 100-id search page, so instead of the 10-minute poll it is crawled *fully* once daily (paged, ids-only, budget-gated) purely as disappearance-detection evidence — it never ingests or evaluates listings. Only a complete crawl counts; detection uses 30h grace (absence from ≥2 consecutive sweeps). Spec 004 US4.1b. | Costs ~1 request per 100 listings per day (≈5,400 req/mo for Kyiv ≤$15k) — the deliberate exception to detection's zero-cost rule. |
| **Relist** | The same car re-posted under a new listing id — detected on ingest against recent (≤30 days) disappearances by normalized-VIN equality, or markId+modelId+year+city with mileage within ±2k km. Marks the old event `is_relist = true`, excluding it from calibration (the car didn't sell). Spec 004 US4.2. | Related but distinct: **AlertedCar** relist de-dup (B12) governs *alerting*, not calibration. |
| **Days on Market (DOM)** | Days a listing has been continuously active since first seen. Drives re-check tier escalation and the `torg`/holding-cost estimate. | Distinct from `dom_days` used specifically in disappearance/calibration records (SPEC-004), which is DOM *at disappearance*. |
| **Re-check tier (ярус)** | A planned SPEC-005 lifecycle frequency bucket, based on score proximity and DOM. It is paused pending demonstrated operator profit. Current production only recovers at most one never-scored listing per profile per 30-minute window; scored listings have no legacy routine recheck ([[0013-budget-stabilization-before-lifecycle-rechecks|ADR-0013]]). | Not the same as `ParameterSet` version. |
| **Budget activity** | One immutable allowed or denied request-budget admission attempt: operation, optional profile, ADR-0009 priority tier, cost, outcome, reason, request fingerprint, and charge state. The `/budget` report groups this history to show actual spend, deferred work, reconciliation, and run-rate forecast. | The aggregate monthly state still enforces the cap; `valuation_ai` has its own atomic allocation inside that cap. |
| **Cohort drift** | Month-over-month change in a cohort's average price (`drift_mo`), applied to `fair_value` to project it forward to the expected sale date instead of using today's snapshot. Computed monthly from RIA's annual average-price series, clamped ±5%/mo. See backlog SPEC-008. | Distinct from the "newest by market" ingestion mode. |
| **Z / ROI** | Monetary output (spec `006-monetary-output-z-roi`) alongside the 0–100 score: `Z` = projected profit in dollars (`X × 0.92 − B − C_fix − C_rec − C_hold`), `ROI = Z / (B + C_fix + C_rec)`. Turns the liquidity and repair-risk *multipliers* into dollar terms (holding cost, expected repair spend) instead of dimensionless factors. Promoted ahead of the remaining spec-003 factors by [[0018-assessment-confidence-and-monetary-output|ADR-0018]]. | Does not replace the score/gate — computed in parallel; adoption decision deferred to after a month of side-by-side comparison. |
| **Assessment confidence** | How well-evidenced *this evaluation* is, as a 0–100% output shown beside the score: computed from zero-cost fields only (`vinChecked`, `hasVinReport`, cohort `sampleSize`/tier, presence of gearbox/engine/body/fuel/generation, description specificity, mileage plausibility). Answers "which car do I drive to see first", not "which ranks higher". [[0018-assessment-confidence-and-monetary-output|ADR-0018]]. **Implemented 2026-08-04** (spec 006 US6.1, T001–T013): shown to the operator as **`Доказова база`** — one line in the alert, the full signed reason list in `/why` — deliberately worded apart from the price core's `Впевненість:` line. Weights live in `ParameterSet.params.confidenceWeights`; absent weights mean the line is omitted, never defaulted. | **Not** the price core's `confidence` (cohort sample size, which multiplies into the score). Assessment confidence is display/ordering only and is **never** multiplied into any score or modifier. |
| **AI analysis** | An admin-triggered, on-demand second opinion from a general-purpose language model on one listing (`/analyze_ai`, spec `017-on-demand-ai-analysis`): structured warnings, an inspection checklist, questions to ask the seller, and a subordinate advisory score. Cached on `(listingId, inputFactHash, promptVersion, modelId)`; separately budgeted; disabled by default. | **Advisory only, permanently** — it cannot influence any score, threshold, or alert, in either direction ([[0019-advisory-only-ai-analysis|ADR-0019]]). Distinct from the AUTO.RIA AI valuation provider, which returns a price estimate and cannot read a description. |
| **Advisory score** | The language model's own 0–10 opinion inside an AI analysis. Rendered in its own labelled section after the warnings, checklist, and questions. | The least defensible number in the system — no ground truth, not reproducible. Never formatted like or placed adjacent to the Total Deal Score (ADR-0019 §8). |
| **Untrusted block** | The delimited region of an AI request carrying counterparty-authored text (the seller description), identified to the model as quoted third-party data and never concatenated into the instruction section. | The description is written by the seller; treating it as instruction would be a prompt-injection surface. Consequence is contained by the advisory-only rule, not by filtering. |
| **Evaluation breakdown** | The full per-parameter view of one evaluation — identity, price and benchmark, cohort, mileage, score decomposition, factors, flags by source, confidence, monetary output, verdict — built once from the persisted explanation and shared by the alert's **Деталі** button, `/why`, and `/check` (spec `016-full-evaluation-breakdown`). | Renders stored values only; never recomputes, never fetches, and states an unavailable parameter with its reason rather than showing zero. |
| **Expected repair cost (`C_rec`)** | Σ of `p(failure) × cost` over the fired red-flags and repair-risk patterns, each carrying a σ — an expected value, not an invoice. | Line-item parts/paint/labour estimates are rejected as false precision (ADR-0018 §7); the system cannot observe the damage. |

## Business rules

_Draft — confirm during SDD:_
- A listing becomes an **Opportunity** only when discount ≥ threshold **and** confidence is sufficient **and** no disqualifying red-flag. See [[profitability-definition]]. Accident presence is **currently** disqualifying; [[0020-graded-accident-risk|ADR-0020]] rules that it should not be, and once the spec-018 phase-3 flip is approved only `severe` severity and salvage will be. Until then the graded verdict is recorded in shadow only.
- Compare within the same **region/currency**; normalize UAH/USD via a stored FX rate.
- Capture new rules here as decided; link contentious ones to an ADR in [[decisions/README]].

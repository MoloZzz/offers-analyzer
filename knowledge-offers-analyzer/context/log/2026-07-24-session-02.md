## Defects found (verified)

1. **429 back-off is dead in the active path** (regression from ADR-0009).
   `auto-ria.source.ts:156` calls `budget.markExhausted()` on HTTP 429, which writes
   only the legacy `rate_budget_windows` hourly row. The active `tryConsume()`
   (`rate-budget.service.ts:42-81`) never reads that table; `remaining()` (its only
   reader) is called nowhere in `src/`. ⇒ after AUTO.RIA rate-limits us, the app does
   **not** back off. The monthly/daily budget still self-limits, but the source's own
   signal is dropped. Medium severity.
2. **`/deal` picks the wrong listing id when a price field has 6+ digits.**
   `extractAutoId` (`telegram-bot.update.ts:456`) returns the *last* 6+-digit run; in
   `onDeal` (line 392) it is handed the full arg (link + `key=value`), so `sell=100200`
   becomes the "id". `rest`-stripping (line 400) uses the *first* 6-digit token (the
   link) — the two disagree. Latent for the ≤$15k niche (prices ≤5 digits); real for
   higher-value niches. No test exists for `telegram-bot.update.ts` at all.
3. **Unrounded `realizedMargin` leaks float artifacts** into two user-facing surfaces
   (`deals-message.ts:44-46` per-deal line; `telegram-bot.update.ts:423` `/deal` reply):
   `buy=8500.05 sell=10200.10 costs=300.02` → `маржа $1400.030000000001`. `marginStats`
   rounds the aggregates, so `/report` is clean; the per-deal path is not. Minor/display.
4. **Non-atomic pool update (TOCTOU).** `ensureDailyBudgetCalculated`
   (`rate-budget.service.ts:137-171`) does a full-entity `stateRepo.save()` off a
   `poolUsed` read earlier; a concurrent `recordConsumption()` atomic increment can be
   clobbered. Low severity today (single-instance, sequential cron); real under scaling.

## Non-blocking observations

- **ADR-0009 tier wiring**: only 4 of 5 priority tiers have callers. The "tier-2
  re-check" bucket is unwired — expected, blocked on SPEC-005 (near-vs-far-threshold
  re-check), documented in [[backlog]]. The "10% cutoff threshold" + 25/50/75%
  sub-bands are implementation choices with no counterpart in the ADR text (nothing to
  validate them against). Progressive-cutoff band edges and call-site tier assignments
  are untested; one test (`rate-budget.spec.ts:320`) is mislabeled ("never denies tier-1"
  but asserts `allowed === false`).
- **ADR-0009 "non-negotiable" ~1 req/2s token bucket** is absent from the codebase; only
  the 10-min cron + sequential awaiting provides cadence.
- **Sweep**: `MAX_SWEEP_PAGES = 250` permits 251 fetches (cap checked after the page-0
  call); cosmetic, self-consistent with the test. 30h `SWEEP_GRACE_HOURS` boundary is
  not isolated in a test (generic cutoff math is boundary-tested only at 24h).
- **Disappearance** (all checks pass): `checkRelist`'s "stop at first match" multi-
  candidate branch is untested; `detectionMode` live/backfill split hardcodes 24h
  `GRACE_HOURS` even when a candidate was selected under the 30h sweep grace — likely
  intentional, worth an author confirm.

validation only.

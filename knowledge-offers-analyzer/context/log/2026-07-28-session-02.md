# Session log - 2026-07-28 (02)

## Goal

Turn the review of the business approach and future roadmap into durable knowledge-base changes.

## Decisions and plan changes

1. Added [[0011-evidence-gated-scoring-rollout|ADR-0011]]. A candidate `k`, factor activation,
   threshold change, or future auto-apply now needs a readiness report, persisted explanation
   provenance, validation review, and explicit operator approval. Fifteen closed deals authorize
   a review, not an automatic production change.
2. Added [[SPEC-009]] as a P0 backlog specification. Actual and forecast API spend by profile,
   operation, and priority tier must be visible before SPEC-005 or another expensive profile is
   enabled. This closes ADR-0009's verification debt.
3. Extended SPEC-004 with US4.3a: a calibration-readiness report for candidate `k`, including
   exclusions, fallback tier, bootstrap interval, cohort stability, and the `k >= 0.97`
   falsification path. A disappearance and last asking price are now consistently documented as
   proxies rather than a confirmed sale/transaction price.
4. Raised B23 persisted evaluation explanations to a P0 rollout gate. It records the facts and
   `ParameterSet`/threshold that applied when an alert was made, so historical decisions are
   reproducible without another source call.
5. Re-cut the active execution order: B23 + SPEC-009 first, keep SPEC-004 data collection running,
   then enable SPEC-005, validate `k`, and only then apply `k` with the first factor bounds.

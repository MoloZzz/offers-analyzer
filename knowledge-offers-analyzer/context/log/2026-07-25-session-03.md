# 2026-07-25 — session 03 — deployment artifacts

Closes finding #5 of [[2026-07-25-session-02]] (partially): "no Dockerfile for
the app, no supervisor config despite ADR-0008". Decision recorded as
[[0011-containerized-deploy-migrate-on-start|ADR-0011]].

## Added

- `Dockerfile` — multi-stage. `builder`: `npm ci` → `nest build` → `npm prune
  --omit=dev`. `runtime`: node:20-alpine + tini, prod `node_modules` + `dist/` +
  `config/`, non-root `node` user, TCP healthcheck.
- `docker-entrypoint.sh` — `migration:run` against the compiled datasource, then
  `exec` the app. `set -eu`, so a broken migration fails container start.
- `.dockerignore` — excludes the vault, `specs/`, `.specify/`, `tools/`, `test/`,
  `.env*`, and `config/search-profiles.json`.
- `docker-compose.yml` — added the `app` service (`restart: unless-stopped`,
  `depends_on` postgres healthcheck, profiles file mounted read-only); postgres
  gained `pg_isready` healthcheck + restart policy.
- `package.json` — `migration:run:prod` / `migration:revert:prod`.

## Constraints discovered while writing it

- **The existing `migration:run` cannot run in a prod image.** It uses
  `typeorm-ts-node-commonjs`, i.e. `ts-node` + `typescript`, both devDeps. Hence
  the compiled path: `node ./node_modules/typeorm/cli.js migration:run -d
  dist/common/database/data-source.js`. Works unchanged because the glob in
  `buildDataSourceOptions()` is already `*.{ts,js}`.
- **No `@Controller` exists anywhere in `src/`** — `app.listen()` runs but every
  route 404s, so an HTTP healthcheck would fail on a healthy container. Used a
  node TCP connect instead.
- **`process.cwd()` reads**: `config/heuristics/*.json` (`valuation/factors/tables.ts`)
  and `config/search-profiles.json` (`profiles.service.ts`) — so `WORKDIR /app`
  must contain `config/`. Heuristics are baked in (committed); the profiles file
  is mounted (gitignored operator data, kept out of image layers).
- **Node as PID 1 ignores SIGTERM** (it installs no handler) → tini as PID 1.

## Verification

- `npm run build` clean; `dist/main.js` and
  `dist/common/database/migrations/*.js` present as expected.
- `node ./node_modules/typeorm/cli.js migration:show -d dist/.../data-source.js`
  → all 15 migrations discovered and reported applied. This is the exact
  invocation the entrypoint uses, so the prod migration path is proven.
- **The image itself was not built** — no Docker daemon on the dev machine at the
  time. `docker compose up -d --build` is unverified end-to-end.

## Still open

- No CI workflow builds/publishes the image (session-02 follow-up, unaddressed).
- No `/health` HTTP endpoint → the container healthcheck can only prove the
  socket is open, not that polling is alive.
- Migrate-on-start assumes a single app instance.

# Agent policy snippet

Merge this into an existing repository policy; do not replace project-specific safety or quality
rules.

Before a non-trivial change, use the knowledge system progressively:

1. Read the context orientation, current handoff, and latest dated session log.
2. Run node ai-infra/engine/v.mjs brief -- "<Roadmap note>" and open the configured index.
3. Use find and show to read the smallest canonical owner of the fact.
4. Read focused code only when implementation evidence is needed.

During work, record session facts in context/log/. Before completion, promote durable product
intent, requirements, architecture rules, decisions, and delivery status to their canonical
curated owners. After an input to generated knowledge changes, run build, then check --strict.

The context zone is background and handoff material, not a second roadmap or specification. Do
not assume this policy is automatically loaded by every agent runtime.
